);

    EmployeeID INT PRIMARY KEY,
    FirstName VARCHAR(50) NOT NULL,
    LastName VARCHAR(50) NOT NULL,
    Department VARCHAR(50),
    HireDate DATE,
    Salary DECIMAL(10,2) NOT NULL
);

QUESTION 1: INNER JOIN

QUESTION 4: FULL OUTER JOIN
Retrieve all customers and all orders, whether matching or not.

ANSWER (SQL FOR MYSQL):
SELECT c.CustomerID, c.FirstName, c.LastName,
       o.OrderID, o.OrderDate, o.TotalAmount
FROM Customers AS c
LEFT JOIN Orders AS o ON c.CustomerID = o.CustomerID
UNION ALL
SELECT c.CustomerID, c.FirstName, c.LastName,
       o.OrderID, o.OrderDate, o.TotalAmount
FROM Customers AS c
RIGHT JOIN Orders AS o ON c.CustomerID = o.CustomerID
WHERE c.CustomerID IS NULL
ORDER BY CustomerID, OrderID;

OUTPUT:
+------------+-----------+----------+---------+------------+-------------+
| CustomerID | FirstName | LastName | OrderID | OrderDate  | TotalAmount |
+------------+-----------+----------+---------+------------+-------------+
|          1 | John      | Doe      |     101 | 2023-07-01 |      150.50 |
|          1 | John      | Doe      |     103 | 2023-08-12 |      650.00 |
|          2 | Jane      | Smith    |     102 | 2023-07-03 |      200.75 |
|          2 | Jane      | Smith    |     105 | 2024-03-15 |      850.00 |
|          3 | Aarav     | Patel    |     104 | 2024-01-20 |     1200.00 |
|          3 | Aarav     | Patel    |     106 | 2024-06-05 |      450.00 |
|          4 | Mia       | Shah     |    NULL | NULL       |        NULL |
+------------+-----------+----------+---------+------------+-------------+
7 rows in set (0.025 sec)

REASON:
MySQL does not directly support FULL OUTER JOIN. The LEFT JOIN returns all customers, and the second query adds any unmatched orders. UNION ALL combines them.

QUESTION 5: SUBQUERY
Find customers who have placed orders worth more than the average order amount.

ANSWER (SQL):
SELECT DISTINCT c.CustomerID, c.FirstName, c.LastName, o.TotalAmount
FROM Customers AS c
JOIN Orders AS o ON c.CustomerID = o.CustomerID
WHERE o.TotalAmount > (SELECT AVG(TotalAmount) FROM Orders)
ORDER BY o.TotalAmount DESC;

OUTPUT:
+------------+-----------+----------+-------------+
| CustomerID | FirstName | LastName | TotalAmount |
+------------+-----------+----------+-------------+
|          3 | Aarav     | Patel    |     1200.00 |
|          2 | Jane      | Smith    |      850.00 |
|          1 | John      | Doe      |      650.00 |
+------------+-----------+----------+-------------+
3 rows in set (0.030 sec)

REASON:
The subquery calculates the average order amount (583.54 approximately). The outer query returns orders greater than that average.

QUESTION 14: RUNNING TOTAL
Calculate the running total of TotalAmount for each order.

ANSWER (SQL):
SELECT OrderID, OrderDate, TotalAmount,
       SUM(TotalAmount) OVER (
           ORDER BY OrderDate, OrderID
           ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS RunningTotal
FROM Orders
ORDER BY OrderDate, OrderID;

OUTPUT:
+---------+------------+-------------+--------------+
| OrderID | OrderDate  | TotalAmount | RunningTotal |
+---------+------------+-------------+--------------+
|     101 | 2023-07-01 |      150.50 |       150.50 |
|     102 | 2023-07-03 |      200.75 |       351.25 |
|     103 | 2023-08-12 |      650.00 |      1001.25 |
|     104 | 2024-01-20 |     1200.00 |      2201.25 |
|     105 | 2024-03-15 |      850.00 |      3051.25 |
|     106 | 2024-06-05 |      450.00 |      3501.25 |
+---------+------------+-------------+--------------+
6 rows in set (0.010 sec)

REASON:
SUM() OVER() accumulates the current row's amount with all previous amounts in date order. It is useful for cumulative sales reporting.

QUESTION 15: RANK ORDERS
Rank orders by TotalAmount using RANK().

ANSWER (SQL):
SELECT OrderID, TotalAmount,
       RANK() OVER (ORDER BY TotalAmount DESC) AS OrderRank
FROM Orders
ORDER BY OrderRank, OrderID;

OUTPUT:
+---------+-------------+-----------+
| OrderID | TotalAmount | OrderRank |

|     102 |      200.75 |         5 |
|     101 |      150.50 |         6 |
+---------+-------------+-----------+
6 rows in set (0.013 sec)

REASON:
RANK() gives rank 1 to the largest amount. Equal values share the same rank, and the next rank may be skipped if there is a tie.

QUESTION 16: DISCOUNT USING CASE
Orders > 1000 get 10% off; orders > 500 get 5% off.

ANSWER (SQL):
SELECT OrderID, TotalAmount,
       CASE
           WHEN TotalAmount > 1000 THEN 10
           WHEN TotalAmount > 500 THEN 5
           ELSE 0
       END AS DiscountPercent,
       ROUND(TotalAmount *
           CASE
               WHEN TotalAmount > 1000 THEN 0.10
               WHEN TotalAmount > 500 THEN 0.05
               ELSE 0
           END, 2) AS DiscountAmount,
       ROUND(TotalAmount - TotalAmount *
           CASE
               WHEN TotalAmount > 1000 THEN 0.10
               WHEN TotalAmount > 500 THEN 0.05
               ELSE 0
           END, 2) AS AmountAfterDiscount
FROM Orders
ORDER BY OrderID;

OUTPUT:
+---------+-------------+-----------------+----------------+---------------------+
| OrderID | TotalAmount | DiscountPercent | DiscountAmount | AmountAfterDiscount |
+---------+-------------+-----------------+----------------+---------------------+
|     101 |      150.50 |               0 |           0.00 |              150.50 |
|     102 |      200.75 |               0 |           0.00 |              200.75 |
|     103 |      650.00 |               5 |          32.50 |              617.50 |
|     104 |     1200.00 |              10 |         120.00 |             1080.00 |
|     105 |      850.00 |               5 |          42.50 |              807.50 |
|     106 |      450.00 |               0 |           0.00 |              450.00 |
+---------+-------------+-----------------+----------------+---------------------+
6 rows in set (0.004 sec)

REASON:
CASE checks conditions from top to bottom. It calculates the discount percentage, discount amount, and final amount after discount. The conditions use > exactly as specified.

QUESTION 17: SALARY CATEGORY
Categorize employee salaries as High, Medium, or Low.

ANSWER (SQL):
SELECT EmployeeID, CONCAT(FirstName, ' ', LastName) AS EmployeeName,
       Department, Salary,
       CASE
           WHEN Salary >= 70000 THEN 'High'
           WHEN Salary >= 50000 THEN 'Medium'
           ELSE 'Low'
       END AS SalaryCategory
FROM Employees
ORDER BY Salary DESC;

OUTPUT:
+------------+--------------+------------+----------+----------------+
| EmployeeID | EmployeeName | Department | Salary   | SalaryCategory |
+------------+--------------+------------+----------+----------------+
|          3 | David Brown  | IT         | 72000.00 | High           |
|          5 | Noah Davis   | Marketing  | 60000.00 | Medium         |
|          2 | Susan Lee    | HR         | 55000.00 | Medium         |
|          1 | Mark Johnson | Sales      | 50000.00 | Medium         |
|          4 | Emma Wilson  | Finance    | 45000.00 | Low            |
+------------+--------------+------------+----------+----------------+
5 rows in set (0.009 sec)

REASON:
CASE assigns a salary category based on the assumed thresholds: High >= 70000, Medium >= 50000 and < 70000, otherwise Low.
